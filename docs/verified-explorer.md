# Verified explorer boundary

Enable `hellas-chain/verified-explorer` for the portable verifier and `wasm-client`
for a browser/Worker WebSocket transport. The canonical block decoder, certificate
checks, query binding, proof bundle, and `VerifiedStore` contract are shared code.
The existing native follower keeps its Commonware archive; the Worker supplies a
transactional SQLite implementation of `VerifiedStore`.

Provision a `hellas_genesis::TrustDocument` through authenticated deployment
configuration. Never bootstrap it from the same indexer whose answers it verifies.
The document has `schema_version: 1`, `network_id: "hellas-devnet-1"`, the lowercase
`genesis_sha256` of the shipped genesis bytes, and a nonempty `epochs` array. Each
epoch supplies `epoch`, `start_height`, exclusive `end_height` (or null), and a
96-character lowercase compressed BLS MinPk `threshold_identity`. Start at height
zero, leave no gaps or overlaps, and increase epoch IDs strictly. A finite final
interval rejects future heights until the trusted configuration is updated.

`trust_sha256` is SHA-256 of `serde_json::to_vec(&TrustDocument)`, not the original
JSON text. Its canonical form has no whitespace; document fields appear in order
`schema_version,network_id,genesis_sha256,epochs`; epoch fields appear in order
`epoch,start_height,end_height,threshold_identity`; `end_height` is always present
with JSON null for an open interval. All validated strings are ASCII and integer
fields use unsigned decimal without padding. Distribute the exact trusted document
with independently installed verifiers. A copy embedded in a web page is evidence
metadata, not an independent trust anchor.

`ProofBundle` has the same fields in serde JSON and protobuf (the field numbers
are specified by the `prost::Message` definition). JSON byte vectors are arrays of
integers. `ExplorerVerifier::verify` checks the pinned trust identifier, devnet,
epoch schedule, threshold certificate, block/certificate round, canonical block
bytes, payload, height, state root, and requested block or transaction identifier.
Transaction identifiers hash the canonical chain transaction encoding using
`transaction_digest`. `VerifiedBlock` exposes only verified block data for rendering.
`observed_at_ms` is advisory and is intentionally not certified; valid finality
does not establish that an answer is the newest available.

Backends must atomically store immutable canonical evidence and a monotonic head
cursor, rejecting conflicts at the same height or payload. Historical cache fills
may retain older blocks without moving the cursor backward. Cache eviction must
preserve the head cursor. Re-verify stored evidence with the current pinned trust
configuration before rendering. `VerifiedStore` futures do not require Send, so a
Cloudflare Durable Object can implement the same boundary as a native process.

Address summaries and ownership lists currently have no consensus-authenticated
completeness proof. This block proof API does not certify those claims. Deployments
must leave them unavailable until the consensus owner commitment and proof API
are implemented. No live threshold key, trust reset, or deployment is generated by
this library; an operator must supply the authenticated threshold schedule.

## Native private origin

`hellas-cli chain indexer serve --rpc wss://relay.example/ws --trust trust.json
--storage-dir /var/lib/hellas/explorer --listen 127.0.0.1:8788` starts a native
verified follower and a loopback-only HTTP origin. Point a Cloudflare Tunnel at
that listener and protect the external hostname with an Access service-token
policy. The process never downloads its trust configuration from the RPC peer.

`/api/v1/blocks/{latest|height|payload}/proof` and
`/api/v1/transactions/{digest}/proof` return the shared ProofBundle, defaulting to
JSON and selecting protobuf for `Accept: application/x-protobuf`. Native canonical
block history remains durable in Commonware. Transaction locators rebuild from
verified archive records on restart; unavailable or not-yet-indexed locators return
503. A known block height can be supplied as `?height=N` to resolve a transaction
without waiting for the locator. Every response is reverified before serving.

The initial origin runner requires one open epoch zero because the native marshal
currently uses a constant provider. The portable verifier understands height-key
rotation; the native marshal provider and validator rotation require coordinated
upgrades before activating a rotated schedule. Address routes remain unavailable.
